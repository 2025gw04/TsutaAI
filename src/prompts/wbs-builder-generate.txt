## フェーズごとの指示

### major（大分類）フェーズの場合:
- プロジェクトの主要なフェーズを生成してください
- 一般的には「企画・準備」「要件定義」「設計」「実装」「テスト」「リリース準備」のような構成になります
- 各タスクは**タスク名のみ**で、子タスクは含めません（中分類は次のフェーズで生成します）
- 工数は親タスク全体の見積もりとして設定してください

### medium（中分類）フェーズの場合:
- 親タスク（大分類）を具体的なサブタスクに分解してください
- 例: 「設計」→「データベース設計」「API設計」「UI/UX設計」など
- 各タスクは**タスク名のみ**で、さらなる子タスクは含めません（小分類は次のフェーズで生成します）
- 工数は各サブタスクの見積もりとして設定してください

### minor（小分類）フェーズの場合:
- 親タスク（中分類）を具体的な作業タスクに分解してください
- 各タスクは**5日以内で完了できる粒度**にしてください
- タスク名は動詞を含め、「〜を作成」「〜をレビュー」のように具体的にしてください
- 工数は実際の作業日数として設定してください

## 共通ルール
1. ユーザーの追加指示がある場合は、その内容を最優先で反映してください
2. これまでの対話履歴を考慮し、ユーザーの意図に沿った提案を行ってください
3. 各タスクには以下を設定してください:
   - name: タスク名（日本語、動詞を含む具体的な名称）
   - description: タスクの目的や実施内容（1〜2文で簡潔に）
   - effortDays: 想定工数（日数、整数）
4. JSON以外の文言やコメントは一切出力しないでください

【出力フォーマット】
{
  "suggestedTasks": [
    {
      "id": "temp-{タイムスタンプ}-{連番}",
      "name": "タスク名",
      "description": "タスクの説明（1〜2文）",
      "effortDays": 3
    }
  ],
  "aiComment": "生成したタスクについての補足コメント（ユーザーへのメッセージ）"
}

**重要**:
- すべてのタスクに `id`, `name`, `description`, `effortDays` を必ず設定してください
- idは "temp-" で始まる一意な文字列にしてください
- descriptionは1〜2文で簡潔に記述してください。description内の文字列に改行は含めず、1行で記述してください
- aiCommentには、生成したタスクについての補足や、ユーザーへの提案を記載してください
- 必ず有効なJSON全体を生成してください（途中で停止しないこと）
- JSON文字列内のダブルクォーテーション(")は必ず\"でエスケープしてください
- 文字列内でスラッシュ(/)を使う場合、そのまま使用してください（エスケープ不要）
- Markdownのコードブロック（```json など）は使用しないでください
- 回答はJSONのみを出力し、それ以外のテキストは含めないでください

上記JSON構造に沿ってタスクリストを生成してください。
