## 割り当てロジック

1. **スキルマッチング**: タスクに必要なスキルを持つメンバーを優先
2. **負荷分散**: 現在のタスク数が少ないメンバーを優先（ただし1人あたり最大3タスク）
3. **スキルレベル**: タスクの複雑度とメンバーのスキルレベルを照合
4. **既存割り当て**: 既に担当者がいるタスクは提案しない
5. **人員の上限**: 各メンバーには1〜3件のタスクを割り当てることを原則とする
   - 1件: リーダーシップが必要な大規模タスクの場合
   - 2〜3件: 通常の作業負荷（推奨）
   - 3件超: 提案しない（人員を追加するか、タスク分割を検討）
6. **並行実行の促進**: 依存関係がないタスク群は、異なるメンバーに割り当てて並列消化できるように分散させること。リソースが空いているメンバーを最大限活用すること。

## 求める出力

以下のJSON形式で、割り当て提案を生成してください：

```json
{
  "assignments": [
    {
      "taskId": "タスクID",
      "taskName": "タスク名",
      "assignedTo": "推奨担当者名",
      "reason": "この担当者を推奨する理由（スキルマッチング、負荷状況など）",
      "confidence": 0.85
    }
  ]
}
```

**confidence**: 割り当ての信頼度（0.0〜1.0）
- 0.9以上: 高確信（スキル完全一致、負荷適切、割り当てタスク数が1〜2件）
- 0.7〜0.9: 中確信（スキル部分一致、負荷やや高い、または割り当てタスク数が3件）
- 0.7未満: 低確信（スキル不一致だが消去法で選択、または割り当てタスク数が3件以上）

## 追加ルール

**提案不可の状況**:
- メンバーが既に3件以上のタスク割り当てを受けている場合は、新たな割り当て提案をしない
- その場合、assignmentsから除外し、理由を記載する代わりに、新しいメンバーの追加またはタスク分割を推奨してください

上記を踏まえて、最適な割り当て提案をJSON形式で出力してください。
