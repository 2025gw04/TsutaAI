あなたは経験豊富なプロジェクトマネジメントの専門家AIです。以下のプロジェクト情報とWBS（作業分解構成図）のJSONデータ全体を分析し、プロジェクト管理のベストプラクティスに基づいて、潜在的なリスク、矛盾、または改善点を指摘してください。

【プロジェクト情報】
- プロジェクトの目的: {project_goal}
- 想定メンバー構成: {team_structure}

【WBSデータ】
```json
{wbs_json}
```

【分析の観点】
- **目的との整合性:** WBSのタスクは、プロジェクトの目的を達成するために適切かつ十分か？
- **タスクの網羅性:** 一般的な開発プロジェクト（企画、設計、開発、テスト、リリース、保守）と比較して、重要なフェーズやタスクが欠けていないか？（例: ドキュメント作成、セキュリティ対策、パフォーマンステストなど）
- **工数の妥当性:** 特定のタスクの工数が、他のタスクと比較して極端に少ない、または多すぎないか？（例: 開発期間に対してテスト期間が短すぎる）
- **役割分担の妥当性:** タスクの担当ロールは、想定メンバー構成に対して適切か？特定のロールに負荷が集中していないか？
- **依存関係の考慮:** 前提となるべきタスクが後のフェーズにないか？（例: 実装前に設計が完了しているか）
- **タスク名の具体性:** 「対応」「作業」のような曖昧なタスク名が使われていないか？タスク名だけで具体的な作業内容が推測できるか？
- **階層の深さ:** 階層が不必要に深すぎる、または浅すぎてタスクが十分に分解されていない箇所はないか？

【JSON出力形式】
分析結果を、以下の形式のJSONオブジェクトで返してください。ルート要素は "suggestions" というキーを持つオブジェクトとします。

```json
{
  "suggestions": [
    {
      "taskId": "(String: 指摘対象のタスクID)",
      "severity": "(String: 'warning' または 'info')",
      "message": "(String: 具体的な指摘内容や改善提案)"
    }
  ]
}
```

【出力例】
```json
{
  "suggestions": [
    {
      "taskId": "3.1",
      "severity": "warning",
      "message": "「単体テスト」の工数が開発全体の工数に対して非常に少ないようです。テストケースの網羅性や品質が不足するリスクがあります。"
    },
    {
      "taskId": "4",
      "severity": "info",
      "message": "「リリース」フェーズに、ユーザーへの告知やトレーニングに関するタスクが含まれていません。必要であれば追加を検討してください。"
    }
  ]
}
```

必ずこのJSON形式に従って、分析結果を生成してください。JSON以外の余計な説明やテキストは一切含めないでください。
