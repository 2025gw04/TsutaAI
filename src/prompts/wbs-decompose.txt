あなたは熟練のプロジェクトマネージャーです。以下の親タスクを、成果物が明確なサブタスクに分解してください。

**重要**: すべての出力は日本語で記述してください。タスク名、説明、成果物などのすべてのテキストフィールドは日本語で出力する必要があります。

【親タスク情報】
- タスク名: {task_name}
- タスクの説明: {task_description}
- 開始日: {start_date}
- 終了日: {end_date}
- 工数: {effort_days}日
- 担当ロール: {assignee_role}
- 成果物: {deliverable}

【プロジェクト情報】
- プロジェクト名: {project_name}
- チームメンバー: {team_members}

【チームの現在の負荷状況】
{team_workload}

【祝日情報】
以下の祝日は営業日から除外してください：
{holidays}

{existing_subtasks}

【作成ルール】
0. **既存サブタスクがある場合**: 既存のサブタスク情報を参考にして、改善版を生成してください。既存のタスクは削除され、新しいサブタスクのみが使用されます。

1. **工数の分配**:
   - サブタスクの工数合計は親タスクの工数（{effort_days}日）を超えてはいけません
   - 可能な限り親タスクの工数に近づけること
   - 並行実行可能なタスクは積極的に並行化して効率化すること

2. **期限の設定**:
   - 親タスクの開始日（{start_date}）から終了日（{end_date}）の範囲内で設定すること
   - 各サブタスクに適切な開始日と終了日を設定すること
   - **営業日（土日祝を除く）で計算すること**
   - **工数は営業日数で設定すること（土日祝は含めない）**
   - 依存関係を考慮して、前のタスクが終わってから次のタスクが始まるように設定すること
   - 例: 金曜日開始、工数2日 → 金曜日、月曜日（土日スキップ） → 終了日は月曜日

3. **担当者の割り当て**:
   - タスクの内容に最も適したスキルを持つメンバーを割り当てること
   - チームの負荷状況を考慮し、特定のメンバーに偏らないようにすること
   - 各メンバーの現在のタスク数を確認し、負荷が高いメンバーへの割り当てを避けること

4. **サブタスクの粒度**:
   - 親タスクを完了させるために必要な作業を3〜6件のサブタスクとして列挙する
   - 各サブタスクは単独で完結する粒度とし、成果物と担当ロールを必ず設定する
   - 可能であれば前提となる順序（依存関係）を記載する

【出力フォーマット】
```json
{
  "subtasks": [
    {
      "name": "サブタスク名",
      "description": "サブタスクの目的や実施内容を1〜2文で記述",
      "effort_days": 2,
      "start_date": "2025-01-10",
      "end_date": "2025-01-12",
      "actual_start_date": null,
      "actual_end_date": null,
      "deliverable": "主要成果物",
      "assignee_role": "担当ロール",
      "assignee": "担当者名（チームメンバーから選択）",
      "priority": "high/medium/low",
      "dependencies": ["依存するサブタスク名やID。なければ空配列"]
    }
  ]
}
```

**重要**:
- **すべてのテキストフィールド（name、description、deliverableなど）は必ず日本語で出力してください**
- JSON以外の文字列は一切含めず、数値は数値型で出力してください
- 日付はYYYY-MM-DD形式で出力してください
- assigneeは必ずチームメンバーから選択してください
- priorityはタスクの重要度に応じてhigh/medium/lowから選択してください
- actual_start_dateとactual_end_dateは、新規タスクの場合はnullを設定してください
- 既存サブタスクの改善版を生成する場合は、既存の実績日（actual_start_date、actual_end_date）を引き継いでください
