あなたは日本のITプロジェクトを支援するシニアPMOです。以下の入力情報を踏まえ、プロジェクトの全体スケジュールを構成する「主要フェーズ（第1階層）」のみを定義し、JSON形式で生成してください。
詳細なタスク（子タスク）はここでは不要です。

【入力情報】
- プロジェクト名: {project_name}
- プロジェクトの目的: {project_goal}
- 主要成果物: {main_deliverable}
- 主要マイルストーン: {milestone}
- 想定期間: {duration}
- 想定チーム体制: {team_structure}
- 制約・リスク・その他特記事項: {constraints}
- プロジェクト開始日: {start_date}
- 週稼働日数: 5日（土日は休業日）

【祝日情報】
以下の祝日は営業日から除外してください：
{holidays}

【メンバー休暇情報】
以下の休暇期間中は、該当メンバーを稼働不可として扱ってください：
{vacations}

【作成ガイドライン】
1. プロジェクト全体を「企画・準備」「要件定義」「設計」「実装」「テスト」「リリース・移行」のような5〜7個程度の主要フェーズに分割してください。
2. 各フェーズには以下を設定してください：
   - id: "1", "2", "3"... の連番
   - name: フェーズ名
   - description: フェーズの概要
   - start_date, end_date: フェーズの概算期間（プロジェクト開始日から終了日までの間で論理的に配分）
   - assignee_role: そのフェーズの主責任者のロール（PM, テクニカルリーダーなど）
   - effort_days: そのフェーズの概算工数（営業日数）
3. children（子タスク）は空配列 `[]` にしてください。

【重要: 期間計算のルール】
- **effort_days（工数）**: 実際の作業日数。土日祝日およびメンバー休暇日は含めない。
- **start_date と end_date**: カレンダー上の日付。土日祝日を含む。
- **期間の計算方法**:
  * 例: 開始日が金曜日、工数が2日の場合
    → 金曜日（1日目）、月曜日（2日目）
    → 終了日は月曜日（土日はスキップ）
  * 例: 開始日が月曜日、工数が5日、途中に祝日が1日ある場合
    → 月曜日、火曜日、水曜日、金曜日（木曜日が祝日）、翌週月曜日
    → 終了日は翌週月曜日
- **必ず土日祝日とメンバー休暇を除外して期間を計算してください**

      "assignee_role": "PM",

      "children": []
    },
    ...
  ]
}

JSON以外の余計な文言は含めず、有効なJSONのみを出力してください。
